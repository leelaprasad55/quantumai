# QuantumLearn AI — Project Report

## Executive Summary

QuantumLearn AI is an interactive quantum-computing education platform. It combines a structured 24-module learning curriculum with assessments, personalised learning roadmaps, circuit construction, simulations, AI tutoring, learner progress tracking, and a multi-framework Quantum Lab.

The project source is maintained in the public GitHub repository: https://github.com/leelaprasad55/quantumai

The primary current issue is deployment architecture. The published Render application is a **Static Site**, while the code compiler requires a Python/FastAPI server. The frontend therefore loads, but Qiskit, PennyLane, and Cirq execution cannot complete until the application is deployed as a Render Web Service.

## Client-Facing Capabilities

- Guided curriculum from beginner to expert quantum-computing topics.
- 24 modules covering mathematics, qubits, gates, circuits, Qiskit, quantum algorithms, QML, noise, hardware, cryptography, and optimisation.
- Adaptive learning roadmap based on learner assessment results and prerequisites.
- Interactive circuit builder with standard and parameterised quantum gates.
- Quantum Lab for generating and running Qiskit, PennyLane, and Cirq circuits, plus OpenQASM export.
- Measurement counts, probabilities, circuit visualisation, and explanations.
- Context-aware AI tutor with an offline fallback.
- Knowledge tests, skill map, achievements, saved experiments, and learner-progress tracking.
- Administrative analytics and user-management capabilities.

## Technical Architecture

| Layer | Implementation |
|---|---|
| Frontend | React 19, Vite, React Router |
| UI and visualisation | Custom CSS, KaTeX, Chart.js, Monaco Editor, Canvas |
| API | FastAPI and Uvicorn |
| Quantum execution | Qiskit + Aer, PennyLane, Cirq |
| Authentication and data | Supabase |
| AI assistant | Groq API with fallback responses |
| Intended hosting | Render Docker Web Service |
| Source control | GitHub, `main` branch |

The intended deployment is a single Docker-backed service. The frontend is built with Vite, then FastAPI serves both the compiled frontend and `/api` routes from one domain. This lets the application submit quantum jobs safely to the backend.

## Quantum Compiler Status

The compiler supports the code shapes generated by the Quantum Lab:

- **Qiskit:** circuit creation, standard and rotation gates, `measure_all()`, and list-based measurement mappings.
- **PennyLane:** standard gates, rotations, literal list/tuple wires, and numeric or `math.pi` angles.
- **Cirq:** standard gates and generated `rx`, `ry`, and `rz` rotations.
- **OpenQASM:** export-only; it is not currently executable from the editor.

Validation completed locally:

- 16 backend tests passed.
- 15 frontend tests passed.
- Production frontend build passed.

## Current Deployment Issue

The existing Render URL, https://quantumai-gkl0.onrender.com, is configured as a Static Site. A static site can only serve frontend files; it cannot run Python, FastAPI, Qiskit Aer, PennyLane, or Cirq.

```text
Browser loads the React UI
        ↓
User selects Run in the Quantum Lab
        ↓
The Static Site cannot execute /api/quantum/execute
        ↓
The browser receives an incomplete response and reports execution failure
```

This is a hosting configuration issue, not a syntax issue in the displayed Qiskit program.

## Required Deployment Configuration

Create a new Render **Web Service** from the repository `main` branch with:

```text
Runtime: Docker
Dockerfile Path: quantum_backend/Dockerfile
Docker Build Context: .
```

Configure the following environment variables in Render:

```text
SUPABASE_URL
SUPABASE_ANON_KEY
IBM_QUANTUM_API_KEY
IBM_QUANTUM_INSTANCE
QBRAID_API_KEY
GROQ_API_KEY
CORS_ORIGINS
```

After deployment, use the new Web Service URL as the production application URL. The existing Static Site should be retired once the Web Service is confirmed working.

## Security and Operations

Provider credentials must remain private and be configured only as Render environment variables or untracked local `.env` files. If any credential has been exposed in a screenshot, chat, commit, or public location, revoke and replace it immediately.

Recommended actions:

1. Rotate any exposed provider credentials.
2. Create the Render Docker Web Service.
3. Configure the required environment variables.
4. Deploy the current `main` branch.
5. Verify that `/api/health` returns a successful JSON response.
