Executive summary: QuantumLearn AI is a React/Vite single-page quantum-computing learning platform. React renders the interface, Supabase manages identity and persistent data, a custom JavaScript engine simulates small quantum circuits locally, and a Supabase Edge Function connects the AI tutor to Groq.

4. Runtime Architecture

Browser loads index.html
  -> src/main.jsx mounts React
  -> BrowserRouter enables routes
  -> AuthProvider restores Supabase session
  -> ProgressProvider loads progress and skills
  -> App selects public or authenticated layout
  -> Page components call contexts, utilities, and Supabase
  -> React state updates the interface
  -> Supabase persists user data

5. Authentication Flow

  1. Registration calls supabase.auth.signUp() with name, education, goal, and avatar metadata.
  2. A database trigger creates a profile with the safe default role student.
  3. Login calls signInWithPassword(); Google login uses Supabase OAuth.
  4. AuthContext fetches the matching profile and creates the frontend user object.
  5. New users are redirected to /test; assessed users go to /dashboard.
  6. Logout ends the Supabase session and clears local user state.

6. Learning and Progress Flow

Register/login
  -> knowledge assessment
  -> skill percentages calculated
  -> personalized roadmap generated
  -> module opened
  -> topic learned and marked complete
  -> topic_progress saved
  -> module assessment submitted
  -> module_progress saved
  -> activity and skill data updated
  -> dashboard, roadmap, skill map, achievements refresh

7. Adaptive Learning

generateRoadmap() averages the 14 skills. Beginners below 20 receive the full 24-module path. More advanced learners receive modules related to weak skills and their selected goal, with completed modules removed and prerequisites considered. Module 24 is always appended.

8. Quantum Circuit Flow

User places gates
  -> operation list changes
  -> simulateCircuit() initializes |000...0>
  -> operations are applied as matrix-vector multiplications
  -> final amplitudes become probabilities
  -> charts, Bloch sphere, state text, and measurements update
  -> optional save, share, gate analytics, or AI explanation

The simulator is local JavaScript. It supports H, X, Y, Z, S, T, Rx, Ry, Rz, CNOT, SWAP, CZ, measurement, tensor products, reduced states, and global-phase-aware comparisons.

9. AI Tutor Flow

Student asks question
  -> Supabase ai-tutor Edge Function
  -> server-side GROQ_API_KEY
  -> Groq model fallback chain
  -> Markdown response
  -> chat message persisted
  -> if unavailable: direct Groq key, then offline keyword response

The circuit explainer uses the same server path and can fall back to a local structured explanation generated from the simulator.

10. Quantum Lab and Race

The Quantum Lab supports educational presets such as Bell, GHZ, W, teleportation, Grover, QPE, and Deutsch-Jozsa, as well as noise models, histograms, fidelity, and code generation for Qiskit, PennyLane, Cirq, and OpenQASM.

The hardware dispatch screen is a local simulation. It creates a fake job ID and uses timers; it does not submit to IBM Quantum, Azure Quantum, Amazon Braket, or another real provider.

The Quantum Race animates classical and quantum complexity comparisons for Grover, Shor, Deutsch-Jozsa, Simon, HHL, and QFT.

12. Security and Engineering Risks

Credential warning: A live Groq key was previously found in the environment template during project preparation. It was removed from the tracked template, but the key must be revoked and replaced. Any VITE_* value is visible in the browser bundle, so Groq secrets must live only in Supabase Edge Function secrets.
  • AI responses are rendered with dangerouslySetInnerHTML without a proper Markdown sanitizer.
  • The AI Edge Function uses wildcard CORS and has no explicit caller authorization or rate limiting.
  • User-entered API keys are stored in localStorage.
  • Lab fidelity is displayed as 0-100 but the database constraint expects 0-1.
  • Lab experiment counters, XP, streaks, and some question counters are not consistently incremented.
  • Some quizzes display scores without persisting them through recordTestScore().
  • Prerequisites are shown in the UI but are not fully enforced for direct module URLs.
  • The reusable circuit puzzle is not connected to the main application flow.
  • The topic circuit challenge has operation/amplitude handling inconsistencies.
  • Some admin cohort and gradebook data is generated in the frontend and is not durable.
  • There are no automated tests, lint checks, or type checks.
